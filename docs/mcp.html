Native MCP server (MVP)

skygrep mcp exposes a stdio Model Context Protocol server so agents can call skygrep as structured tools instead of scraping shell output.

This is an MVP: two tools that delegate to the existing retrieval pipelines. It is not marketed as a production-hardened MCP product yet.

Client status: protocol is generic stdio MCP. Cursor has been verified end-to-end (Connected + 2 tools + live agent_context call). Claude Desktop / Claude Code / other hosts use the same tools but need their own config + a successful call — do not treat Cursor success as universal out-of-the-box.

Tools

Ops commands (index / watch / setup / …) stay on the CLI. Tool parameters live in each tool’s schema — fewer tools, richer arguments.

Why not the official mcp SDK by default?

The official PyPI mcp package currently needs Python ≥ 3.10 and a heavy dependency stack. skylakegrep stays on Python 3.9+ with a lean stdlib JSON-RPC + Content-Length framing implementation (binary stdio as of 0.7.5).

Install & configure

pip install skylakegrep==0.7.5
skygrep index /absolute/path/to/your/repo

Cursor (~/.cursor/mcp.json or project .cursor/mcp.json):

{
  "mcpServers": {
    "skygrep": {
      "command": "skygrep",
      "args": ["mcp", "--path", "/absolute/path/to/your/repo"],
      "env": {}
    }
  }
}

Starter file: examples/mcp.json. Full notes also in mcp.md.

Positioning

Apache-2.0 · offline · CLI / agent_context harness · MCP MVP usable — a retrieval component for existing agents, not a do-everything agent platform.
